# Plan: Dark Mode Feature (2026-07-29)

## 1. Scope

- Add a Dark Mode toggle button to the `NavigationBar` component.
- Configure Tailwind CSS v4 for class-based dark mode via a `@custom-variant`
  in `app/globals.css` (this project has no `tailwind.config.ts` — v4 is
  CSS-first).
- Persist the user's theme preference (via `next-themes`) so it survives
  page reloads.
- Update existing components (Hero, Projects, Contact, Footer, NavigationBar)
  with `dark:` variants using the existing zinc color scale.

## 2. Context

- Next.js (App Router) + Tailwind v4, confirmed via `package.json`
  (`"tailwindcss": "^4"`) and `postcss.config.mjs` (`@tailwindcss/postcss`).
- No `tailwind.config.ts` exists anywhere in the repo.
- `app/globals.css` currently drives `--background`/`--foreground` via
  `@media (prefers-color-scheme: dark)` — no class-based mechanism yet.
- Every existing component (`HeroSection`, `ProjectsSection`, `Footer`,
  `NavigationBar`, `ContactSection`) uses the Tailwind **zinc** scale
  exclusively — no other gray family appears anywhere.
- `next-themes` is not currently a dependency.

## 3. Technical Plan

- **Library:** Install `next-themes` — handles persistence and hydration
  safety (a Next.js/React concern, independent of Tailwind version).
- **Tailwind v4 configuration:** add a custom variant in `app/globals.css`,
  right after the existing `@import`:
  ```css
  @import 'tailwindcss';

  @custom-variant dark (&:where(.dark, .dark *));
  ```
- **Reconcile existing CSS variables:** replace the current
  `@media (prefers-color-scheme: dark)` block in `globals.css` with a
  `.dark { ... }` selector, since `next-themes` (with `defaultTheme="system"`)
  will already resolve OS preference into the `.dark` class — avoids two
  competing mechanisms.
- **Provider:** wrap `app/layout.tsx`'s children in
  `<ThemeProvider attribute="class" defaultTheme="system">`.
- **Toggle component:** new `app/components/ThemeToggle.tsx`, `'use client'`,
  using `useTheme()`, rendered only after mount (`useEffect` + `mounted`
  state) to avoid hydration mismatch. Inline SVG sun/moon icons — no new
  icon library, matching the project's zero-UI-dependency convention.
- **Wire into `NavigationBar`:** add `<ThemeToggle />` into the existing nav
  row.
- **Component updates:** add `dark:` variants to Hero/Projects/Footer/Contact
  using the existing zinc scale (e.g. `dark:bg-zinc-900`, `dark:text-zinc-100`)
  — no slate, no new color family.

## 4. Failure Points & Edge Cases

- **Hydration Mismatch:** toggle must only render after client mount.
- **System Preference:** must default to OS preference (`defaultTheme="system"`)
  when no explicit choice was made.
- **Contrast:** text must stay readable against dark backgrounds.
- **Silent no-op risk (Tailwind v4 specific):** if the `@custom-variant dark
(...)` line is ever missing, `dark:` utilities silently fall back to
  `prefers-color-scheme`-only — the toggle renders but visibly does nothing,
  with no error. Explicit review checklist item for this.
